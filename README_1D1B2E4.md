# Functional 1D.1B.2E.4 — Atomic Member / Family Core

**Do not enable production feature flags.** No invitations, member consent records,
program enrollment or subscriptions are created. `/register` remains disabled.

This patch adds an admin-only (Super Admin) explicit POST endpoint:
`/api/admin/public-registration/provisioning/member-family`
JSON: `{ "request_id": "<uuid>", "claim_id": "<uuid>" }`

Requires `ATOM_REGISTRATION_MEMBER_FAMILY_PROVISIONING_ENABLED=true` *only in an isolated test environment*.
RPC: `atom_complete_registration_member_family_v1(uuid,uuid,uuid)`.

- PostgreSQL row-locks registration request, checks verified email, claim, recorded Auth ID,
  Auth provenance metadata and staff role.
- Adults: completes the *empty* profile generated by Auth signup, rejecting populated profiles.
- Minors: requires a parent Auth account marked `user_metadata.account_type=family_parent`;
  atomically creates Family, Guardian, dependent Member without a child Auth account.
- Fails closed for parent Auth accounts already carrying a `profiles` row (including
  previously created ambiguous accounts), existing guardian links, or a child identity
  matching an existing profile. Such cases require separate manual review.
- Atomically marks request `invitation_pending`; no invite is sent.
- Repeated calls with same claim return `ALREADY_PERSISTED` instead of another row.

**Critical integration:** `publicRegistrationAuthProvisioning.ts` sets `user_metadata.account_type=family_parent`
for newly created parent Auth identities. Existing accounts created before this patch are NOT
silently modified. Existing accounts need a future supervised identity-reconciliation workflow.

**Tests before enabling:** isolated adult + child happy paths; rollback on constraint error;
repeat identical request; different claim; forged provenance; parent's member profile; existing
family guardian; duplicate child identity; mismatched verified email; unauthorized RPC.

SQL verification:
```
SELECT p.proname, p.prosecdef,
 has_function_privilege('anon',p.oid,'EXECUTE') AS anon_execute,
 has_function_privilege('authenticated',p.oid,'EXECUTE') AS authenticated_execute,
 has_function_privilege('service_role',p.oid,'EXECUTE') AS service_role_execute
FROM pg_proc p JOIN pg_namespace n ON n.oid=p.pronamespace
WHERE n.nspname='public' AND p.proname='atom_complete_registration_member_family_v1';
```
Expected: true,false,false,true.
